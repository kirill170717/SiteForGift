# Сервер доставки на VPS

Для небольшого подарочного сайта достаточно одной виртуальной машины с 1–2 ГБ памяти и постоянным диском. Вариант — [Timeweb Cloud](https://timeweb.cloud/services/cloud-servers), Ubuntu 24.04, публичный IPv4. Тариф, срок оплаты и стоимость IP проверить перед заказом. Сервер и домен ещё не арендованы.

У Timeweb Cloud исходящий SMTP-порт 465 по умолчанию закрыт. До оплаты уточнить возможность его разблокировки для личной отправки подарочной карты через Gmail. Разблокировка доступна в панели или через поддержку: [ограничения провайдера](https://timeweb.cloud/docs/cloud-servers/limitations).

## Подготовить сервер

1. Установить Docker Engine и Compose по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
2. Назначить публичное DNS-имя API, например `gift-api.example.com`. Это только пример: использовать собственное имя. A-запись направить на IPv4 сервера. Публиковать AAAA только если IPv6 сервера настроен.
3. Разрешить входящие TCP 80 и 443. SSH ограничить своим адресом. Порт 8787 не публиковать. Разрешить исходящее соединение с `smtp.gmail.com:465`.
4. Клонировать публичный репозиторий. Приватную папку `.private/deliveries` и `.private/smtp.env` перенести через SSH/SFTP. Не класть их в общедоступную папку веб-сервера.
5. На сервере задать права на хранилище для UID 1000, под которым работает Node. Выполнять команды из корня этого проекта:

```sh
sudo chown -R 1000:1000 .private/deliveries
sudo chmod -R go-rwx .private/deliveries
chmod 600 .private/smtp.env
```

В `.private/smtp.env` заполнить пароль приложения Gmail самостоятельно. `GIFT_ALLOWED_ORIGIN` оставить `https://kirill170717.github.io`. Не вводить пароль в команду запуска или публичные переменные GitHub.

## Запустить

```sh
export GIFT_API_HOST=gift-api.example.com
docker compose up -d --build
```

Заменить имя примера реальным. [Caddy](https://caddyserver.com/docs/automatic-https) получит сертификат при корректном DNS и доступных портах 80/443. Настройка Compose не публикует порт API напрямую; PDF и состояние остаются в приватной папке на постоянном диске. HTTP-журнал запросов не включён.

В GitHub добавить переменную Actions `GIFT_DELIVERY_API_URL=https://<реальное-имя-API>` и запустить workflow Pages. Открыть новую личную ссылку и пройти к форме: она должна показать статус готовности, а не демо. Для проверки Gmail использовать отдельный тестовый PDF и собственный адрес, не расходуя ссылку настоящего подарка.

Не масштабировать сервер на несколько экземпляров. Сохранять `.private/deliveries`, включая `state.json` и `send.lock`, при обновлении и переносе. Резервные копии содержат карту и адрес получателя; хранить их приватно. При неоднозначной SMTP-ошибке сначала проверить почту, не удалять состояние автоматически.

Docker и Caddy локально не запущены: на рабочем компьютере Docker отсутствует. Конфигурация подготовлена для проверки после выбора сервера и DNS.
