# Бесплатная доставка: Google Apps Script и Google Drive

Этот вариант работает в личном Google-аккаунте: сайт остаётся на GitHub Pages, закрытый PDF хранится в Google Drive, а письмо отправляет MailApp от владельца проекта Apps Script. VPS, отдельный домен и пароль приложения Gmail не требуются. Текущий лимит обычного аккаунта — [100 получателей в сутки](https://developers.google.com/apps-script/guides/services/quotas); квоты Google могут меняться.

После квеста кнопка открывает форму доставки на странице Google в новой вкладке. Адрес вводится дважды, затем подтверждается отдельной кнопкой. Сам квест остаётся на Pages. Получателю не нужен Google-аккаунт, если приложение опубликовано с доступом **Anyone**, а выполнение — от владельца.

## Когда появится PDF

1. Войти в Google Drive именно как `kirill170717@gmail.com` и загрузить PDF. В доступе оставить **Restricted / Ограниченный доступ**. Не добавлять других пользователей или ссылочный доступ. Код также проверяет приватность файла перед отправкой.
2. Взять ID файла из его адреса вида `https://drive.google.com/file/d/<ID>/view`. ID не является ключом доступа к закрытому файлу, но хранить настройки всё равно приватно.
3. Отредактировать `.private/email.json`: тема, сообщение, подпись. Запустить из проекта:

```sh
node scripts/prepare-google-delivery.js "ID_ФАЙЛА_ИЗ_DRIVE"
```

Скрипт создаёт `.private/google-<id>/` с готовыми файлами и `.private/delivery-link-<id>.txt` с личной ссылкой. Хеш ключа сохраняется в настройках, исходный ключ — только в личной ссылке. Эти папки исключены из Git. Для этого варианта не использовать `prepare-delivery.js`: он готовит другой сервер.

## Один раз подключить аккаунт

1. Открыть [Google Apps Script](https://script.google.com/) под `kirill170717@gmail.com`, создать собственный проект «Доставка подарка».
2. Перенести файлы из сгенерированной приватной папки: `Code.gs`, `Setup.gs`, HTML-файл `Form`, HTML-файл `Email_<id>`. Имена HTML-файлов в редакторе указываются без `.html`.
3. В настройках редактора включить отображение `appsscript.json` и заменить его содержимое сгенерированным. В нём разрешения отправки писем, чтения Drive и просмотра адреса аккаунта для проверки владельца при настройке. MailApp не получает доступ к входящим письмам. Разрешение `drive.readonly` позволяет проекту читать файлы владельца; проект не передавать другим редакторам.
4. Открыть **Setup.gs**. В списке функций над кодом выбрать **configureGift** (без подчёркивания в конце) и нажать **▶ Выполнить**. `configureGift_` остаётся приватной служебной функцией и в этом списке не появляется. `configureGift` проверяет аккаунт запуска и вызывает приватную настройку; анонимные посетители настроить подарок не могут. Владелец самостоятельно проходит авторизацию Google. При предупреждении о непроверенном приложении авторизацию завершает владелец после проверки собственного кода. Пароли, токены и данные авторизации в чат не присылать.
5. Если запуск настройки не запросил разрешения, выбрать в редакторе `doGet` и запустить, чтобы Google предложил авторизацию остальных объявленных разрешений. Этот запуск ничего не отправляет. Не запускать `sendGift` для авторизации.
6. **Deploy → New deployment → Web app**. **Execute as: Me**, **Who has access: Anyone**. «Anyone with Google account» потребует регистрации получателя и не подходит. Сохранить публичный URL, заканчивающийся `/exec`. URL `/dev` предназначен только для владельца.
7. В GitHub → Settings → Secrets and variables → Actions → Variables добавить **GIFT_GOOGLE_SCRIPT_URL** с полученным URL. `GIFT_DELIVERY_API_URL` оставить пустым или удалить. URL приложения публичный и не содержит ключа подарка. Запустить workflow Pages снова.

Если настройки Google-аккаунта или организации не разрешают анонимное приложение, этот вариант нельзя считать подключённым без проверки. Для личного Gmail проверить доступ через браузер без входа в Google перед вручением подарка.

## Проверка и следующие подарки

Настоящее приложение пока не опубликовано: нет PDF и авторизации владельца Google. Локальные тесты подменяют MailApp и DriveApp, проверяют исходное PDF-вложение, запрет повторной отправки, секретную ссылку, приватность и лимит отправки. Они не проверяют доступность реального развёртывания Google.

Сначала создать отдельный подарок с тестовым PDF и отправить его на свой адрес. Проверить письмо и вложение, затем повторить отправку по той же ссылке: второго письма быть не должно. Открыть готовую форму без Google-аккаунта. Настоящую карту подготовить с новой ссылкой.

Для следующего подарка добавить новый `Email_<id>` и заменить содержимое `Setup.gs` новой настройкой. Запустить `configureGift`, не удаляя существующие Script Properties, затем обновить версию развёртывания. Старые записи `gift:<id>` и `state:<id>` сохраняют защиту от повторов.

Состояние записывается в Script Properties **до** вызова MailApp. Одновременные запросы блокирует Script Lock. Ошибка почтового сервиса сохраняет `uncertain`; после сбоя возможен `sending`. Такие состояния требуют ручной проверки почты и не повторяются автоматически. Удаление `state:<id>` снимает защиту от дублей.

Отозвать ссылку можно, добавив `"revoked": true` в JSON свойства `gift:<id>`; уже отправленное письмо это не отменяет. Ссылка разрешает получение её владельцу, а не подтверждает личность. Получатель может переслать ссылку до отправки и PDF после неё.

Ключ передаётся между Pages и Google в URL-фрагменте `#`, затем в запросе `google.script.run`. Он не включается в параметры HTTP-адреса. В браузере Google не публикуются ID файла Drive, хеш ключа, настройки письма или исходный PDF. Скрипт не имеет публичного метода скачивания файла и не записывает ключ или адрес получателя в свои журналы.

Документация Google: [Web apps](https://developers.google.com/apps-script/guides/web), [MailApp](https://developers.google.com/apps-script/reference/mail/mail-app), [приватные функции](https://developers.google.com/apps-script/guides/html/communication#private_functions).
