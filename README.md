# Бюро подарков

Подарочный квест с финалом «Сюрприз — на почту». Получатель указывает адрес, повторяет его и подтверждает отправку. Сервер отправляет оформленное письмо **от kirill170717@gmail.com** с оригинальной подарочной картой в PDF во вложении.

## Что опубликовано

Сайт: https://kirill170717.github.io/SiteForGift/

GitHub Pages публикует интерфейс и демонстрацию письма. Общая ссылка показывает тестовую форму: **письмо из демо не отправляется**. Настоящая отправка требует PDF, настройки Gmail и отдельного сервера. GitHub Pages серверные программы не запускает.

Квест: проверка адресата, капча настроения, умение принимать подарки, сканирование сияния, код `0418`, ложная ошибка 418 и форма доставки. Прогресс сохраняется отдельно для каждой личной ссылки. Квест не является проверкой личности.

## Добавить PDF и подготовить письмо

1. Поместить полученный от магазина PDF в `.private/gift.pdf`. Можно также передать путь к PDF при запуске скрипта.
2. Отредактировать `.private/email.json`: тема, личное сообщение, подпись. Образец находится в `examples/email.example.json`; локальная копия уже создана.
3. Запустить `node scripts/prepare-delivery.js`. Или указать путь: `node scripts/prepare-delivery.js "путь/к/карте.pdf"`.

Скрипт копирует PDF без изменений в `.private/deliveries/<id>/gift.pdf`, сохраняет текст письма и хеш секретного ключа в `manifest.json`. Личная ссылка сохраняется в `.private/delivery-link-<id>.txt`. Ссылка и исходные данные не печатаются в журнал.

Папку `.private/deliveries/<id>/` перенести в приватное хранилище сервера. Получателю отправить соответствующую ссылку целиком. PDF, ключ, настройки SMTP и данные получателя **не добавлять в GitHub**. `.private/`, `.env`, PDF и EML исключены из Git; не обходить защиту командой `git add -f`. Сборка Pages использует список разрешённых файлов. Локальный сервер не выдаёт приватные файлы по HTTP.

Ограничение вложения этой версии — **10 МБ**. Проверяется размер и сигнатура PDF. Сайт не извлекает номер карты, PIN или баланс. Файл передаётся как оригинальное вложение; действительность карты не проверяется.

## Подключить Gmail

Нужны Node.js 22 и зависимости: `npm ci --ignore-scripts --no-audit --no-fund`.

Скопировать `examples/smtp.env.example` в `.private/smtp.env` (локальная копия уже создана). Заполнить **GMAIL_APP_PASSWORD** паролем приложения Gmail. Обычный пароль аккаунта не использовать. Пароль приложения создать самостоятельно в [аккаунте Google](https://myaccount.google.com/apppasswords); для этого обычно нужна двухэтапная проверка. Не присылать пароль в чат и не коммитить его. [Инструкция Google](https://support.google.com/accounts/answer/185833).

Настройки:

- `GMAIL_USER=kirill170717@gmail.com`;
- `GMAIL_APP_PASSWORD` — приватный пароль приложения;
- `GIFT_ALLOWED_ORIGIN=https://kirill170717.github.io` — origin сайта;
- `GIFT_DATA_DIR` — путь к приватной папке deliveries, по умолчанию `.private/deliveries`;
- `GIFT_SERVER_HOST`, `GIFT_SERVER_PORT` — адрес и порт, по умолчанию `127.0.0.1:8787`.

Запуск: `node --env-file=.private/smtp.env server/app.js`.

Используется `smtp.gmail.com:465`, TLS с проверкой сертификата, HTML и текстовая версия письма. Диагностическое логирование SMTP отключено. Без учётных данных письма не отправляются. Gmail может отклонить вход с нового сервера или ограничить отправку; проверить настройку перед вручением подарка. [Документация Nodemailer](https://nodemailer.com/usage/using-gmail/).

## Сервер в интернете

Разместить Node-сервер на хостинге с постоянным приватным диском и **HTTPS**. Подготовлен `Dockerfile`; `.dockerignore` не включает приватные файлы в образ. Подключить приватную папку как `/data/deliveries` с разрешением записи для пользователя `node` (UID 1000). Пароль Gmail передать через секреты хостинга. Использовать одну инстанцию сервера с постоянным диском: потеря состояния снимает защиту от повторной отправки.

Для VPS подготовлены `compose.yaml` и `deploy/Caddyfile`: приватное хранилище, закрытый порт Node и автоматический HTTPS. [Пошаговый запуск и выбор хостинга](deploy/vps.md). Требуются арендованный сервер, DNS-имя API и доступ к SMTP Gmail; инфраструктура ещё не создана.

В GitHub → Settings → Secrets and variables → Actions → Variables добавить **GIFT_DELIVERY_API_URL** с HTTPS-адресом сервера, например `https://gift-api.example.com`. Это публичный адрес сервиса, а не секрет. Запустить публикацию Pages заново. Настройка попадает в `delivery-config.json`. Пока адрес пуст, личная форма сообщает, что отправитель ещё подключает доставку.

HTTPS-прокси не должен записывать Authorization и тела запросов в журналы. Ограничить частоту обращений и размер запросов на прокси. Backend принимает JSON до 2 КБ и не имеет публичных маршрутов загрузки/скачивания PDF.

## Защита и повторная отправка

Личная ссылка содержит случайный ключ 32 байта после `#`; к Pages эта часть HTTP-запросом не передаётся. В API ключ передаётся по HTTPS в заголовке Authorization. На сервере хранится SHA-256 ключа; сравнение не зависит от совпавших символов. Проверка origin дополняет авторизацию.

Получатель повторяет адрес и нажимает отдельную кнопку подтверждения. Сервер разрешает один адрес и прикладывает только свой приватный PDF; подмена файла или темы из браузера игнорируется. Состояние хранится на диске; эксклюзивная блокировка защищает от одновременных запросов. После принятия Gmail карта не отправляется повторно или на другой адрес.

**SMTP не гарантирует однозначный результат при обрыве соединения.** До обращения в Gmail записывается `sending`; при ошибке — `uncertain`. Такие записи нельзя автоматически очищать или повторять: Gmail мог принять письмо. После аварии сервера проверить почту отправителя и получателя. Удалять `state.json` или `send.lock` допустимо только после ручной проверки отсутствия отправки; удаление снимает защиту от дублей.

Для отзыва ссылки установить `"revoked": true` в приватном `manifest.json`. Это блокирует новые обращения, но не отменяет начатую отправку. Получатель может переслать полную ссылку до отправки, PDF или письмо. Подтверждение личности и владения указанным email отсутствует. PDF и адрес обрабатывает Gmail как почтовый провайдер.

## Локальная проверка

```sh
npm ci --ignore-scripts --no-audit --no-fund
node --test
node scripts/build.js
node scripts/serve.js
```

Интерфейс: http://127.0.0.1:4173. Письмо: http://127.0.0.1:4173/email-preview.html. Для локального API установить `GIFT_ALLOWED_ORIGIN=http://127.0.0.1:4173`. Тесты проверяют MIME и API с заглушкой; **реальных писем тесты не отправляют**.

Прежняя зашифрованная JSON-карта сохранена в исходниках, но финал использует PDF-доставку. Старые ссылки `#gift=...` не подходят: подготовить новую через `prepare-delivery.js`.
