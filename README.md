# Бюро подарков

Сайт-квест для необычного вручения подарочной карты «Золотого яблока». Обычные HTML, CSS и JavaScript. Общая ссылка показывает демо; личная ссылка открывает зашифрованную карту в финале.

## Сценарий

1. Проверка адресата с шуточными ответами.
2. Капча настроения: выбрать все шесть качеств.
3. Проверка умения принимать подарки.
4. Сканирование сияния до 140% (без камеры).
5. Открытие хранилища по коду `0418`.
6. Ложный финал «Ошибка 418», обещание и раскрытие демо-карты.

Квест сохраняет этап в браузере. Звук включается только по нажатию кнопки. Есть мобильная версия, управление с клавиатуры, поддержка уменьшенной анимации, копирование номера и скачивание тестовой карты в SVG.

## Локальный запуск

Нужен Node.js 22 или новее. Дополнительные пакеты не нужны.

```sh
node scripts/serve.js
```

Открыть `http://127.0.0.1:4173`. Проверки: `node --test`. Сборка: `node scripts/build.js`, результат в `dist/`.

## GitHub Pages

Рабочий процесс `.github/workflows/pages.yml` проверяет проект и публикует только файлы сайта из `dist/` после обновления `main`. В Settings → Pages выбрать источник **GitHub Actions**. На GitHub Free репозиторий должен быть публичным; приватный репозиторий требует поддерживающего Pages плана.

Демо опубликовано: `https://kirill170717.github.io/SiteForGift/`.

## Тестовые данные и персонализация

Открытые тестовые значения и код задания находятся в `quest.js`. Действующий сертификат в этот файл не добавлять. Тексты экранов — в `app.js`; вступление — в `index.html`; оформление — в `styles.css`.

## Подготовка личной карты

1. Создать папку `.private/` и скопировать в неё `examples/card.example.json` под именем `card.json`. В рабочей копии уже подготовлен тестовый файл.
2. В `.private/card.json` указать сумму, номер карты и PIN. Для действующей карты установить `"demo": false`. Все поля, кроме `demo`, должны быть строками. Самостоятельно проверить номер и PIN: сайт не обращается к магазину и не проверяет баланс.
3. Запустить:

```sh
node scripts/prepare-gift.js
```

4. Скрипт создаст `gifts/<случайный-id>.json` с шифротекстом и `.private/recipient-<id>.txt` с полной личной ссылкой. Скрипт не печатает ключ или карту в журнал.
5. Добавить в коммит **только** файл `gifts/<id>.json`, отправить коммит в GitHub и дождаться успешной публикации Pages.
6. Отправить получателю ссылку из соответствующего `recipient-<id>.txt` целиком, включая всё после `#`. Эти данные не добавлять в README, задачи, коммиты или публичные сообщения.

`.private/`, `.env` и файлы ключей исключены из Git. Это защита от случайного добавления; команда `git add -f` может её обойти. Сборка использует список разрешённых файлов, не копирует `.private/` и отклоняет незашифрованные файлы в `gifts/`. Локальный сервер также не выдаёт приватные файлы по HTTP.

## Как защищена карта

Карта шифруется **локально** через Web Crypto: AES-256-GCM, случайный ключ 32 байта, новый IV 12 байт для каждой карты. Подлинность шифротекста и ID проверяется при расшифровке. Открытый файл содержит только версию, алгоритм, случайный ID, IV и шифротекст.

Ключ находится во фрагменте личной ссылки после `#`. Этот фрагмент браузер не отправляет в HTTP-запросе. При обращении за картой ключ не включается в адрес запроса или заголовки. Страница устанавливает `no-referrer`. После финального задания браузер скачивает шифротекст и расшифровывает его своим ключом. Неверная или неполная ссылка, изменённый шифротекст и недоступный файл показывают закрытый экран, без подмены настоящего подарка демо-картой.

В `localStorage` хранится только этап квеста отдельно для каждого ID. Ключ и расшифрованная карта туда не записываются. Карта существует в памяти страницы и появляется в финале. HTTPS или локальный адрес обязательны для Web Crypto.

### Границы доступа

Это доступ по владению ссылкой, без регистрации и подтверждения личности. Обычный посетитель сайта и читатель публичного репозитория не получают ключ. Но **каждый, кто получит полную личную ссылку, сможет открыть карту**. Получатель может переслать ссылку, сохранить карту или сделать скриншот. Квест — часть подарка, а не проверка личности: технически владелец ключа может расшифровать карту без прохождения заданий.

Полная ссылка сохраняется в истории браузера. Владелец компьютера отправителя также может прочитать `.private/`. Берегите эти файлы и канал, через который передаёте ссылку. У карты нет срока доступа или одноразового погашения на уровне сайта. Удаление шифротекста из текущей версии не отзывает копии и историю Git. При утечке ссылки действующий сертификат нужно заменять или блокировать через магазин. Для доступа по личности и управляемого отзыва нужен сервер с авторизацией; эта версия его не использует.

Проверки защиты: `node --test` (неверный ключ, изменение шифротекста/IV/ID, исключение приватных файлов из сборки, отсутствие ключа в HTTP-запросе, безопасное отображение строк).

Документация: [Web Crypto / AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt), [фрагмент URL](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment).

Шрифты загружаются из Google Fonts; при недоступности сервиса используются системные шрифты. Задания работают без сетевых запросов после загрузки страницы. Первое открытие, обновление и загрузка личной карты в финале требуют интернета.

Сайт не является официальным сайтом магазина. Открытое демо содержит вымышленные данные и не подходит для оплаты.
